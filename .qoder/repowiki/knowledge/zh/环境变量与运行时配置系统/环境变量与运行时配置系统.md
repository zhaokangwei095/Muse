本仓库采用基于 `.env` 文件的环境变量配置方案，通过 `dotenv` 库在 Express 服务器启动时加载，配合 Vite 构建工具的前端开发配置，形成统一的环境管理方式。

**加载机制**：
- 后端使用 `dotenv.config()` 在 `server.ts` 启动时加载 `.env` 文件中的环境变量
- 前端通过 Vite 的 `process.env` 访问构建时配置（如 HMR 开关）
- 关键环境变量包括 `GEMINI_API_KEY`（Gemini AI API 密钥）、`APP_URL`（应用部署地址）、`DISABLE_HMR`（开发热更新开关）

**配置分层**：
- 开发环境：`.env.example` 提供模板，实际值由 AI Studio 运行时注入
- 生产环境：通过 Cloud Run 等服务平台的环境变量注入机制
- 构建时配置：Vite 配置文件根据 `DISABLE_HMR` 环境变量动态调整开发服务器行为

**安全约定**：
- API 密钥等敏感信息不提交到版本控制（`.gitignore` 排除 `.env` 文件）
- 服务端对缺失的关键配置进行防御性检查（如 Gemini API key 不存在时返回错误）
- 使用 `process.env.NODE_ENV` 区分开发和生产环境的不同行为

**约束与限制**：
- 所有环境变量必须通过 `dotenv` 加载后才能被代码访问
- 前端无法直接访问后端的 `process.env`，需要通过 API 接口间接获取
- HMR 功能受 `DISABLE_HMR` 环境变量控制，在 AI Studio 环境中默认禁用以避免编辑闪烁
